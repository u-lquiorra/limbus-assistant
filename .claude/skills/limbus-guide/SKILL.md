# Limbus 攻略ガイド執筆

このリポジトリ(Limbus Assistant)の人格・E.G.O データを根拠に、日本語の攻略ガイドを書くための手順。第1〜5章は人格向け。**E.G.O のガイドは第6章の差分(情報源・解析段階の読み方・テンプレート・保存先)を優先し、残りは同じ方針で進める。**
ガイドは読者がそのまま信じて編成・操作するので、**データに無いことを事実として書かない**ことが最優先。

## 1. 情報源と優先順位

| 優先 | 場所 | 内容 |
|---|---|---|
| 1 | `src/data/personas/<code>.json` | スキル(名前・罪悪属性・攻撃タイプ・マッチ威力・コイン・効果文)、パッシブ(必要資源・条件・効果)、用語ツールチップ `keywords` |
| 2 | `src/data/<囚人名>.json` | `statuses`(HP・速度・攻撃/守備Lv・耐性・シーズン・所属)、`skills`(最大威力の要約) |
| 3 | `references/battle-system.md` | バトルシステムの仕組み(マッチ、共鳴、混乱、状態異常など)。wiki のゲームシステム解説から作成 |
| 4 | `.cache/commentary/<code>.md` | wiki の「性能解説」節(勝ち筋・ループ・運用・シナジー)。`npx tsx scripts/extract-commentary.ts <code>` で `.cache/wiki/` から抽出する。**勝ち筋の特定に必ず使う。文章は転載しない** |

- 数値・効果は 1 と 2 から引用する。3・4 と食い違ったら 1・2 を正とし、食い違いをユーザーに報告する。
- 「何が強いか・どう回すか」(勝ち筋)は 4 を最重視する。効果文だけから組み立てると、本領となる動き(例: 蜘蛛の巣の刀 良秀の「天殺」、黒獣-卯 筆頭 ファウストの「奥義ループ」)を注意点扱いにしたり見落としたりする。
- 効果文の「A/B」「A/B/C」は同期化段階ごとの値(低い段階/高い段階)。両方が同時に適用されるわけではない(例: 「呼吸10以上なら加重値+1/呼吸7につき加重値+1(最大2)」は段階で切り替わる)。
- ガイドは同期化Ⅳ(データの効果文に載っている全効果)を前提に書く。データの効果文には「同期化Ⅳで追加」された効果の段階表記がないため、wiki の性能解説で同期Ⅳ追加とされる効果が勝ち筋の成立に関わる場合は「(同期化Ⅳ)」と添える。
- 本文に「wiki の性能解説によれば」「〜とされる」「〜が勧められている」といった出典・伝聞の表記は書かない。wiki の解説は参考にとどめ、内容を理解したうえで自分の言葉で言い切る(出典は frontmatter の `sources` に `wiki性能解説` と書くだけでよい)。
- データと wiki が食い違う点、データで裏付けられない点は、wiki を引き合いに出さず「〜と考えられる」「データからは確認できない」と書く。
- 自分の一般知識(学習データ)で補う場合は「〜と考えられる」と推測であることを明記する。数値を推測で書かない。

## 2. 用語

wikiwiki.jp/lcbwiki の日本語表記に統一する(韓国版・グローバル版の表記は使わない)。

- 囚人: イサン / ファウスト / ドンキホーテ / 良秀 / ムルソー / ホンル / ヒースクリフ / イシュメール / ロージャ / シンクレア / ウーティス / グレゴール
- 罪悪属性: 憤怒 / 色欲 / 怠惰 / 暴食 / 憂鬱 / 傲慢 / 嫉妬
- 攻撃タイプ: 斬撃 / 貫通 / 打撃(略記は 斬 / 貫 / 打)
- 状態異常・用語は人格データの `keywords[].term` の表記をそのまま使う(例: 呼吸、沈潜、破裂、振動、火傷、出血、充電)
- コイン: 「破壊不能コイン」は `unbreakableCoins`(元から)と `unbreakableByEffect`(効果で変化)、パッシブの `unbreakableByEffect` を区別して書く

## 3. 手順

1. **データを読む**: 対象人格の `personas/<code>.json` と、囚人 JSON の該当 `statuses` 要素を読む。
   `wikiUrl` は囚人 JSON の `statuses[].wikiUrl`。
2. **勝ち筋を特定する**: `.cache/commentary/<code>.md` を読み、wiki 編集者がこの人格の本領として挙げている動き(コアループ、最重要ギミック、前提となる編成)を1〜3点に絞る。
   - 各点を効果文で裏付ける(例: 「天究星刀は最大20・攻撃後に10消耗 → 次のターンも10残る」をデータで確認)。裏付けできない部分は書かないか、推測と明記する。
   - 俗称(「奥義ループ」など)は wiki で使われていれば「俗に〜と呼ばれる」として紹介してよい。
   - 性能解説が無い・古い(「解説更新日」が古い)場合はその旨を控え、データからの推測であることを明記する。
3. **役割を判定する**: 効果文とパッシブから、主な役割(アタッカー / デバッファー / タンク・守備 / サポート / 資源供給)と、軸になる状態異常キーワードを特定する。根拠となる効果文を控えておく。
4. **相性候補を探す**: 軸キーワードや所属で他の人格を検索する。
   - 例: `Grep pattern="\"term\": \"破裂\"" path=src/data/personas` → 破裂を扱う人格
   - 罪悪属性の共鳴相手: 囚人 JSON の `skills[].s1.sin` などで同じ罪悪属性の人格を探す
   - 候補は必ず効果文で裏付けを取り、「なぜ噛み合うか」を1文で書く
5. **書く**: 下のテンプレートに沿う。勝ち筋は「ひとことで」と「使い方」の主軸に置き、ギミックの列挙はそれを支える順に並べる。
6. **検証する**: 次の2つのサブエージェントに、ガイドのパスと対象人格コードを渡す。指摘をすべて解消してから完了とする。
   - `guide-strategy-reviewer`: wiki の性能解説と比べて、勝ち筋の欠落・主従の取り違えがないか
   - `guide-fact-checker`: 記述がデータと一致するか(勝ち筋を書き足したら必ず再実行する)
7. **保存する**: `src/data/guides/<code>.md`。

## ひとことで
(1〜2文。勝ち筋=この人格が本領を発揮する動きを必ず含める)

## 主要ギミック
- **ギミック名**: 勝ち筋を支える順に。条件・上限・回数制限はデータどおりに

(勝ち筋に至る手順。序盤の準備 → 本領の動き → 維持の仕方。前提となる編成があれば書く)

## 5. 禁止事項

- データに無い数値・効果を書く(「たぶん威力+2」など)
- wiki の性能解説・シナジー節の文章をそのまま、または言い換えただけで載せる(要約・独自の分析にする)
- 根拠なしの強さランク付け(Tier 表など)
- 他の人格を挙げるときに、その人格のデータを確認しない

## 6. E.G.O ガイド

E.G.O のコード(例 `0108`)は囚人ページの一覧と同じ4桁で、**人格コードと重なる**(人格 0108 とは別物)。ファイル名・キャッシュ名は `ego-` を付けて区別する。

### 6.1 情報源

| 優先 | 場所 | 内容 |
|---|---|---|
| 1 | `src/data/egos/<code>.json` | 覚醒/侵蝕スキル(威力・コイン・効果文)、E.G.Oパッシブ、必要資源 `cost`、耐性 `resistance`、専用効果 `specialEffects`、基本情報 `info`(危険ランク・精神消耗量・攻撃タイプ)、用語 `keywords` |
| 2 | `src/data/<囚人名>.json` の `egos[]` | 一覧の情報(ランク・罪悪属性・攻撃タイプ・必要資源・耐性倍率・備考=入手方法) |
| 3 | `references/battle-system.md` | 資源、精神力、E.G.O侵蝕、罪悪耐性の上書きなど |
| 4 | `.cache/commentary/ego-<code>.md` | wiki の「性能解説」節。`npx tsx scripts/extract-commentary.ts ego-<code>` で `.cache/wiki/ego-<code>.html` から抽出。勝ち筋の特定に必ず使う。文章は転載しない |

食い違ったら 1・2 を正とする点は人格と同じ。

### 6.2 解析段階の読み方

E.G.O は人格の「同期化」ではなく **解析Ⅰ〜Ⅳ** で強化される(Ⅱでパッシブ取得、Ⅲ・Ⅳで数値や効果が強化)。`egos/<code>.json` の効果文・数値には、wiki の文字色から作った印が残っている。

- `〘Ⅲ:…〙` は解析Ⅲで追加・変化する部分、`〘Ⅳ:…〙` は解析Ⅳで追加・変化する部分。印の無い部分は解析Ⅱ以前から有効。
- 値の列 `A/〘Ⅲ:B〙/〘Ⅳ:C〙` は「解析Ⅱ以前 A、Ⅲ B、Ⅳ C」。`A/〘Ⅳ:C〙` なら「Ⅲまで A、Ⅳ で C」。**両方が同時に適用されるわけではない**。
- 効果ごと〘Ⅳ:…〙で囲まれた行は、解析Ⅳで新たに加わる効果(例: 〘Ⅳ:[的中時] 次のターンに束縛2を付与〙)。
- ガイドは解析Ⅳを前提に書き、勝ち筋の成立に解析段階が関わるときは「(解析Ⅲ)」「(解析Ⅳ)」と添える。段階の解析コストや優先度は、データに無いので性能解説を参考に自分の言葉で書く(出典表記はしない)。
- 本文に印(〘 〙)は書かない。
- **解析Ⅴ**: 一部の E.G.O(0102 など、`info` に「解析Ⅴ」の日付がある)は解析Ⅴが実装されている。この場合 `skills` / `passives` が**解析Ⅴの状態**、`earlier.skills` / `earlier.passives` が**解析Ⅰ〜Ⅳの状態**(印付き)。ガイドの本文は解析Ⅴを前提にし、「解析」の枠にⅤの行を足して、Ⅳとの差(`earlier` と本体の差分)を書く。アプリの詳細ページは「解析Ⅴ / 解析Ⅰ〜Ⅳ」のタブで切り替えられる。

### 6.3 E.G.O ならではの観点

- **必要資源と精神力**: 使うには `cost` の罪悪属性の資源が必要(使用で消費)。精神消耗量は `info` の「精神消耗量(覚醒/侵蝕/OC)」。重い資源が編成で賄えるかは勝ち筋の前提になる。
- **耐性の上書き**: 使用中は、その E.G.O の `resistance` に罪悪耐性が切り替わる(battle-system.md)。脆弱・耐性の並びを事実として書き、敵の属性との相性に触れるなら推測と明記する。
- **覚醒と侵蝕**: 侵蝕スキルは精神力が -45 に達したとき強制使用され、敵味方を問わず攻撃することが多い。侵蝕スキルが無い E.G.O(ZAYIN 初期 E.G.O など)もある。攻撃タイプが覚醒と侵蝕で異なる場合はスキルごとの `attackType` を使い分ける。
- **パッシブ**: E.G.O パッシブは解析Ⅱで解放され、使用後の次ターンから戦闘終了まで有効(パッシブ末尾の※注記が条件の根拠)。
- **専用効果**: `specialEffects` はその E.G.O 固有の状態効果(例: 割れた世界、硬化バリア)。仕組みと上限をデータどおりに書く。
- **入手方法**: 一覧の備考(例: S1有償パスLv30、コラボイベント限定)は事実として書いてよい。強さの評価と混ぜない。
- **相性**: 使い手の囚人の人格が、E.G.O の軸キーワード(火傷・破裂など)や資源を供給できるかを、人格データの効果文で裏付けて書く。人格側のデータは `personas/<code>.json` を開いて確認する。

### 6.4 テンプレートと保存先

**短く書く。** 読み手は戦闘前にさっと見るので、全体で 1,000 字前後を目安にする。長くなる内容は削るか、下の枠に分ける。

```markdown
---
code: "0108"
ego: 三千大世界
character: イサン
updated: YYYY-MM-DD
sources: [egos/0108.json, イサン.json, personas/0112.json, wiki性能解説]
---

## ひとことで
(**本当に1文**、60字程度。勝ち筋=この E.G.O が本領を発揮する動きを必ず含める。数値や条件は入れない)

## 主要ギミック
- **ギミック名**: 1項目1〜2文、80字程度まで。勝ち筋を支える順に。条件・上限・解析段階はデータどおりに(4〜5項目まで)

## 使い方
(箇条書き3〜4行。先に何を準備し、いつ撃ち、次に何をするか。細かい数値の再掲はしない)

## 解析
(Ⅱ・Ⅲ・Ⅳごとに1行ずつ。何が変わるか、優先度の目安。本文から分けた枠として表示される)

## 編成・相性
- **[人格名](persona:0112)**: 1文。なぜ噛み合うか(効果文で裏付けたものだけ)
```

- 見出し名はそのまま使う。「解析」と「編成・相性」はアプリが見出しで拾い、それぞれ別の枠で表示する(「解析」は本文の下、「編成・相性」はパッシブの下)。無ければその枠は出ない。
- 相性の人格は `[表示名](persona:<4桁の人格コード>)` と書くと、人格詳細ページへのリンクになる(コードは人格のもの。E.G.O コードではない)。
- 侵蝕スキル・耐性・精神消耗など、詳細ページのスキル欄で見られる値は本文で繰り返さない。使い方に関わる要点だけ書く。

保存先は `src/data/guides/ego/<code>.md`(人格ガイドの `src/data/guides/<code>.md` とは別の場所)。アプリは `guides/ego/` を E.G.O ページ専用に読む。

### 6.5 検証

人格と同じ2つのサブエージェントを使う。依頼文に **「E.G.O のガイド」であること**、ガイドのパス(`src/data/guides/ego/<code>.md`)、E.G.O コードを必ず伝える(人格コードと取り違えないため)。指摘をすべて解消してから完了とする。

- `guide-strategy-reviewer`: `.cache/commentary/ego-<code>.md` と比べた勝ち筋の欠落・主従の取り違え
- `guide-fact-checker`: `egos/<code>.json` と囚人 JSON の `egos[]` との照合(解析段階の取り違えを含む)

## 7. 人格ガイドの「編成・相性」と、おすすめ編成

### 7.1 人格ガイドの「編成・相性」

人格ガイド(`src/data/guides/<code>.md`)の末尾に `## 編成・相性` を置くと、人格ページのパッシブの下に「相性のいい人格」欄として、人格の小さな画像つきで表示される。

- 2人程度。`- **[人格名](persona:人格コード)**(囚人名): 理由1文`。人格名は囚人 JSON の `statuses[].name` と一致させる(同名の人格が複数いるので囚人名を添える)
- 囚人をまたいで選んでよい。理由は、双方の効果文(パッシブの条件・付与・資源の罪悪属性)で裏付けたものだけ
- 候補探しの手がかり: 同じキーワード(例 `Grep "\"term\": \"破裂\"" src/data/personas`)、同じ所属、相手のパッシブが参照する状態(呪殺・呼吸など)

### 7.2 おすすめ編成

編成は構成をデータ、解説をガイドに分ける。

| 場所 | 内容 |
|---|---|
| `src/data/teams.json` | ID・名前・分類・難易度・適性(通常/短期/長期 を ◎〇△✖)・優先枠/自由枠/代替枠/裏置きの人格コード・相性E.G.Oのコード。優先枠と裏置きには役割を1文(`note`)で書く |
| `src/data/team-guides/<id>.md` | 解説。見出しは `## ひとことで` / `## 強み` / `## 回し方` / `## 弱点と対策` |
| `.cache/commentary/teams/<見出し>.md` | wiki の編成ガイドの該当節。`npx tsx scripts/extract-commentary.ts --teams` で抽出。`teams.json` の `source` に見出しを書く |

- 優先枠は囚人を重複させない(テストで検査する)。同名の人格が複数の囚人にいる場合は、効果文を見て該当する方を選ぶ
- メンバーの役割・強み・弱点は、メンバーの効果文で裏付ける。資源の偏りは各人格の S1〜S3 の罪悪属性で確かめる
- 初心者向けは、恒常で手に入る人格だけで優先枠が組めることを条件にする
- 解説では `[人格名](persona:コード)` と `[E.G.O名](ego:コード)` でリンクできる
- 検証は人格ガイドと同じ2つのレビュアー。依頼文に「編成ガイド」であること、`teams.json` の該当 ID、解説のパスを伝える
